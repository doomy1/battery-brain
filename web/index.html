What you are looking at

A simulated 5 Ah lithium-ion cell, and the algorithms a battery management system runs on it. The simulated cell is deliberately more complicated than the model the algorithms were designed with, which is the situation every real battery engineer is in.

1 · State of charge estimation

Coulomb counting integrates current. It has no feedback, so a wrong starting point or a sensor offset is never corrected.

The extended Kalman filter also predicts the cell voltage from a simple circuit model and corrects its estimate whenever the measured voltage disagrees. It recovers from a wrong start, but it inherits every error in its model.

Kalman + neural network adds a small network, trained on simulated lab data, that predicts the voltage error of the circuit model. The filter stays in charge; the network only improves the model it uses.

2 · Fast charging

Model predictive control solves a constrained optimisation every 10 seconds: push as much current as possible while the predicted voltage and temperature stay inside their limits. The optimisation is a quadratic program solved by an interior-point method written from scratch. A Kalman observer estimates unmodelled heating so the controller holds the temperature limit without overshoot.

What runs where

Everything on this page is computed by the project's Python package, running in your browser through WebAssembly. Nothing is pre-recorded and there is no server.

Honest limits

The cell is a simulation, and the network was trained on data from the same simulator, so its accuracy here is an upper bound. On a real cell it would need real test data and would do worse. The ageing slider shows this: the network never saw an aged cell during training.
